# Карьерный бот — демо-версия

Telegram-бот, который помогает подросткам и уставшим от текущей работы взрослым
находить новые направления развития карьеры.

## Что умеет демо

1. **Тест-опросник** (`/test` или кнопка «🧭 Пройти тест на профориентацию»)
   5 вопросов с кнопками → по совпадению тегов интересов подбирает 3 подходящие
   профессии из базы.
2. **Каталог по категориям** (`/professions`) — листание профессий инлайн-кнопками,
   у каждой — подробная карточка.
3. **Свободный запрос** (`/ask`) — пользователь пишет текстом, что его беспокоит,
   бот ищет совпадения по ключевым словам. Это заглушка под полноценную языковую
   модель (см. «Как расширять» ниже).
4. Основное меню — reply-кнопки внизу экрана, не мешают писать текст вручную.

## Запуск

```bash
pip install -r requirements.txt
export BOT_TOKEN=токен_от_BotFather
python bot.py
```

## Архитектура (демо vs боевая версия)

Бот написан на **pyTelegramBotAPI (TeleBot)** — синхронной библиотеке, что
проще для старта и отладки, чем асинхронные аналоги, но накладывает пару
ограничений, важных для боевой версии:

- **Состояние теста хранится в обычном Python-словаре** (`quiz_state`) в
  памяти процесса — это самый простой вариант для демо, но: (1) сбрасывается
  при перезапуске бота, (2) не будет работать, если вы запустите несколько
  процессов бота параллельно (например, для отказоустойчивости) — каждый
  процесс будет видеть только свою часть состояния. Для продакшена лучше
  использовать Redis или БД в качестве хранилища состояния.
- **`bot.infinity_polling()`** — синхронный long polling, блокирует поток на
  каждый запрос к Telegram. Для нагрузки выше нескольких сотен активных
  пользователей стоит перейти на webhook-режим (TeleBot его поддерживает) или
  рассмотреть асинхронную библиотеку (aiogram) — она изначально лучше
  масштабируется под высокую нагрузку за счёт `asyncio`.
- В демо база хранится в `data/professions.json` и грузится в память при
  старте — этого достаточно для тестирования логики. Для продакшена
  рекомендуем **SQLite/PostgreSQL** вместо JSON — чтобы данные можно было
  редактировать без деплоя кода и добавить полнотекстовый поиск.
- **Таблицу пользователей и сессий** — чтобы не задавать один и тот же тест
  повторно и со временем предлагать более точные рекомендации.

## Формат базы данных (для пополнения)

### Таблица/коллекция `professions`

Каждая профессия — такой объект:

| Поле | Тип | Описание |
|---|---|---|
| `id` | строка | Уникальный идентификатор (латиницей, без пробелов) |
| `name` | строка | Название профессии |
| `category` | строка | Категория для каталога (используйте уже существующие категории, где возможно, чтобы не плодить дубли) |
| `short_description` | строка (1 предложение) | Показывается в списках и результатах теста |
| `full_description` | строка (абзац) | Показывается в карточке профессии |
| `required_skills` | список строк | 3–5 ключевых навыков |
| `interest_tags` | список строк | Теги для подбора по тесту — **обязательно из списка ниже** |
| `education_paths` | строка | Куда идти учиться (курсы, вуз, самообучение) |
| `salary_range` | строка | Ориентир по зарплате, с указанием региона и года |
| `growth_outlook` | строка | Короткая справка про перспективы профессии |
| `related_professions` | список строк | Похожие профессии (по названию) |
| `keywords` | список строк | Слова, по которым профессия должна находиться в свободном запросе (демо-поиск) |

**Допустимые `interest_tags`** (использованы в вопросах теста, добавлять новые
теги можно, но тогда нужно доработать и вопросы):
`creative`, `tech`, `people`, `analytical`, `leadership`, `detail`,
`independent`, `science`, `stability`, `freedom`, `income`, `impact`

Сейчас в демо-базе 12 профессий в 6 категориях — этого достаточно, чтобы
протестировать логику, но мало для реального запуска. Рекомендуем расширять
базу до 50–100+ профессий, причём стараться закрыть все теги равномерно —
иначе тест будет однобоко рекомендовать одни и те же направления.

### На будущее: таблица `users` / `quiz_sessions`

Если решите сохранять историю пользователей (для персонализации без повторного
теста), рекомендуемые поля:

- `telegram_id`, `first_seen`, `last_quiz_scores` (JSON), `last_recommended_ids`
- **Важно:** значительная часть аудитории — несовершеннолетние. Собирайте
  минимум данных, не запрашивайте имя/возраст без явной необходимости, и
  заранее продумайте политику конфиденциальности и хранения данных — это
  стоит обсудить с юристом до реального запуска, а не после.

## Как расширять

- **Свободный текстовый запрос** сейчас работает по простому совпадению слов.
  Следующий шаг — подключить языковую модель (например, через Anthropic API)
  с промптом вида «вот база профессий (JSON), вот запрос пользователя, подбери
  3 наиболее подходящих и объясни, почему» — это даст сильно более гибкое
  понимание запроса, включая обработку опечаток, синонимов и эмоционального
  контекста («устал от текущей работы» → нужно уточнять, что именно надоело).
- **A/B тестирование формулировок вопросов** — стоит проверить, какие вопросы
  лучше «разводят» пользователей по разным профессиям.
- **Обратная связь** — после показа рекомендаций можно добавить кнопки
  «👍 подходит / 👎 не подходит», чтобы сырые данные шли на дообучение логики
  подбора.
